# Host extensibility beyond Agent Skills (six hosts)

Research for the portable-skills projection. Verified against live docs on 2026-09-13. Question being answered: OMH has Hermes-coupled capabilities (memory provider, `omh_*` RPC tools, TUI/HUD widgets, chat-wrapper routing) that cannot ship as `SKILL.md` files — are these also undeliverable as *plugins* into the other hosts' stacks, and where do native equivalents already exist?

Method: fetched current documentation for each host (docs mirrors with `.md` twins: code.claude.com, learn.chatgpt.com, cursor.com/docs, opencode.ai/GitHub `sst/opencode`, docs.openclaw.ai, GitHub `badlogic/pi-mono`). All claims below trace to the cited URLs.

## Verdict

**Direct answer: the owner's framing is half right.** It is true that none of the four Hermes-coupled classes can ship as Agent Skills — `SKILL.md` is a prompt artifact; `scripts/` are model-invoked, never host-loaded. But "cannot be delivered as plugins into the other hosts' stacks" is **false for five of six hosts**: every host except pi has a real plugin/tool mechanism, and MCP alone covers Claude Code, Codex, Cursor, opencode, and OpenClaw. pi covers the same ground via a TypeScript extension. The honest boundary is per-capability, not per-host:

- **`omh_*` plugin tools (`omh_todo`, `omh_delegate_route`, `omh_run_summary`)** — non-portable as skills; **feasible as plugins everywhere**. One omh MCP server exposes the RPC surface to 5 hosts; one pi TS extension (`registerTool`) covers the sixth. Cursor even documents loading Claude-compatible hooks, and OpenClaw explicitly consumes Claude/Cursor/Codex plugin bundles, so a single adapter family has unusual reach.
- **File-backed memory provider** — non-portable as a skill; adapter feasibility splits. Native equivalents make an OMH memory adapter **largely redundant** on Claude Code (auto memory), Codex (local memories), and OpenClaw (builtin + active memory) — at most a sync hook. It **fills a real gap** on Cursor, opencode, and pi, which have instructions files only. Note the semantic shift: Hermes injects memory as host-loaded context; on other hosts it becomes model-invoked tool calls, unless a hook injects it (Claude Code, Codex, and Cursor all have `SessionStart`-class hooks; opencode plugins and pi extensions have equivalent events).
- **TUI/HUD widgets** — the genuinely non-portable class. Comparable native surfaces exist only on Claude Code (scriptable `statusLine`) and pi (`ctx.ui.custom` components); Codex's `/statusline` is fixed-item, opencode's TUI is theme/keybind-only, and Cursor's UI extension means writing a VS Code extension. A HUD needs per-host work on 4 of 6 hosts regardless.
- **Chat-wrapper routing (src/wrapper session continuity)** — Hermes-specific host surface; OpenClaw is the only host with a native equivalent (gateway channel routing + agent bindings). Elsewhere it degrades to host subagents/tasks, as the design brief's portable overrides already assume.

**Recommendation:** project skills as planned; treat the Hermes-coupled classes as a two-adapter story (MCP server + pi extension) for tools and memory, and leave HUD widgets and wrapper routing Hermes-only, except where a host's statusline/UI surface makes a cheap port obvious (Claude Code, pi).

**Caveats:** Cursor and Codex docs were restructured onto `cursor.com/docs` and `learn.chatgpt.com` (Markdown twins) during 2026; pi's MCP absence is a repo/docs grep from 2026-09-13, not a spec statement — re-check if pi ships MCP later.
